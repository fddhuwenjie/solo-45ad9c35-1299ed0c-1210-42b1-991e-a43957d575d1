# 生命线通行核算接口

检修人员沿管廊越过开口、绕过立柱时，单件装备额定值合格并不等于整条行走路线安全：
锚点空档会让双钩同时解开，缓冲包完全展开后可能撞上下层管线。本服务把**线路方案 +
人员装备参数**作为修订版本保存，对每一版重算挂接序列与坠落核算，给出是否可通行及
最先失败的位置、动作与计算分量。

挂接体系支持两类对象**混用**：

- **固定点锚（anchor）**：挂点不动，按点锚模型核算（旧版请求完全兼容）；
- **柔性跨段（span）+ 滑梭（shuttle）**：临时水平生命线横跨两个端座，中间可设
  连续/断开式支座，滑梭套在钢索上随作业者移动。坠落后钢索下挠会占用脚下净空，
  端部拉力也可能超出结构承载——按悬索模型给出动态下挠、总坠距与端座/支座反力。

防坠装备支持两种系绳模型：

- **旧等长模型（默认）**：每个连接分别按完整止坠力检查（旧请求完全兼容）；
- **Y 型双腿系绳（`equipment.twin_leg`）**：两条实体腿分别与 A/B 钩永久绑定、
  在汇接器汇合后**共用一个缓冲包**。逐站按松弛量确定接载次序，以能量 + 变形
  协调求缓冲展开量、人体峰值制动力、逐腿张力与锚点合力——同一缓冲能力在整个人
  体上**只计一次**。

技术栈：Python / FastAPI / Pydantic v2 / SQLite（标准库 `sqlite3`）。

## 运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000
# 数据库文件默认 ./lifeline.db，可用环境变量 LIFELINE_DB 指定
```

## 模型概念

一版修订（`PlanPayload`）包含：

| 部分 | 内容 |
|---|---|
| `route.walk_polyline` | 三维行走折线（≥2 点） |
| `route.drop_edges` | 落差边缘：位置、锐边等级 0–3、落差深度（下层楼面 = z − 深度） |
| `route.obstacles` | 障碍物：轴对齐盒 `box` / 竖直圆柱 `cylinder`（如下层管线、立柱） |
| `route.anchors` | 固定点锚：坐标、额定载荷 kN、允许受力方向锥（轴线 + 半角）、`max_users` 多人共用限制 |
| `route.supports` | 柔性跨段端座 / 中间支座：坐标、结构容许反力 kN、允许受力方向锥 |
| `route.spans` | 柔性跨段：端座与中间支座序列、预张力 `pretension_kn`、线密度 `line_density_kg_m`、弹性参数（`axial_stiffness_kn` 或 截面×模量）、`max_sag_m` 挠度限值、`shuttle_pass` 滑梭过支座能力、`max_users` 容许人数 |
| `route.shuttles` | 滑梭：所属跨段、连接器触及余量、本梭容量、自身 `can_pass` 过支座能力 |
| `persons` | 重量、D 环高度、体半径、引用装备 |
| `equipment` | 旧等长模型：绳长、伸长量、缓冲行程、锐边等级、连接器触及余量、最大止坠力；或 Y 型双腿系绳 `twin_leg`（两腿原长/刚度/侧载限值、钩腿绑定、共享缓冲力—行程曲线、最大行程、能量容量、允许夹角） |
| `params` | 离散步距、安全余量、安全带伸长、摆坠阈值、重力加速度、悬索迭代次数/容差 |
| `hook_order` | 人工挂接动作次序（可选）：目标为 `anchor` 或 `shuttle`（attach/switch 二选一），给出后按该次序回放校验；为空则自动生成 |
| `conservative_bounds` | 是否授权在弹性迭代不收敛时采用保守边界（反力按刚性索上界、下挠按 H₀ 几何索形上界），须写理由并在修订 `changes` 中登记 |

### 人工挂接动作次序

`hook_order` 随修订持久化，创建方案、另存修订与历史回看均按该版次序重算动作序列、
失败依据与剖面标注。回放校验规则：

- 同站动作保持输入先后次序；`attach`/`switch` 的目标锚点必须在连接器触及范围内且不超
  `max_users`；`detach` 后另一钩必须仍保持有效连接；
- `attach`/`switch` 若需释放该钩的旧连接，则旧连接断开至新连接建立期间另一钩必须在
  当前站保持有效连接，否则判定换挂链断开；
- 每站处理完动作后（末站除外）至少保留一个有效连接，否则判定换挂链断开；
- 末站仍挂接的钩由引擎补记解钩事件；站点索引越界的动作判为失败；
- 给出了 `hook_order` 的人员按人工次序回放，未给出的人员仍按自动算法生成。
- 使用 Y 型双腿系绳时，动作可带 `leg` 字段指明实体腿；其值必须等于该钩绑定
  的腿（A→LA、B→LB），交叉绑定在请求校验阶段即 422。

## 核算引擎

1. **离散化**：行走折线按 `station_spacing_m` 加密为站点（保留全部顶点）。
2. **触及范围**：站点 D 环（脚底 + `d_ring_height_m`）到锚点距离 ≤ 绳长 + 连接器触及余量，
   该锚点在此站可挂。
3. **挂接序列**：双钩交替前进。某钩锚点在下一站将超出触及范围时，必须在当前站换挂到
   能覆盖下一站的新锚点；换挂期间另一钩保持连接——**任何状态至少保留一个有效连接**。
   当前站无锚可换（或受多人共用限制）即判定**换挂链断开**：继续行进将出现双钩同时解开
   的瞬间。多人共用按 `max_users` 占用锚点容量，前人占满则后人无法建立连接。
4. **逐站坠落核算**（对每个有效连接锚点）：
   - 自由坠距 `FFD = clamp(L + d_z − a_z, 0, 2L)`（锚点低于 D 环则加大）；
   - 总坠距 `= FFD + 伸长量 + 缓冲行程 + 安全带伸长`；总净空 `= 总坠距 + 安全余量`；
   - 可用净空 = 站面 − 下方最高障碍物顶面 / 落差边缘下层楼面；**余量 < 0 即失败**；
   - 摆坠扫掠体：水平偏移超过阈值时，以展开绳长为半径的摆弧上采样 D 环 / 脚底两串
     球体，与障碍物求交；
   - 锚点方向：止坠力方向（锚点→D 环连线）与允许锥轴线夹角 ≤ 半角；
   - 合力：能量法 `F = W·g·(FFD+缓冲)/缓冲`（封顶最大止坠力），**对每个在用锚点**
     核对合力与额定载荷——单人挂接同样核对，多人同时挂接时求和，超限即
     **锚点过载 / 共用锚点过载**；
   - 锐边适配：距落差边缘不超过绳长时，边缘锐边等级不得超过装备锐边等级。
5. **最先失败**：所有失败按（站点序号 → 检查优先级 → 人员序）排序，响应
   `first_failure` 含位置、动作（attach/switch/detach/traverse）、检查项与全部计算分量；
   存在任一失败即 `passable = false`，绝不标为可通行。
6. **剖面标注**：每站给出控制性锚点，自由坠距、所需净空、净空下限标高、可用净空与
   余量，供绘制沿程剖面。

### 柔性跨段（临时水平生命线）核算

1. **站位确定滑梭位置**：把站点水平投影到所属 bay（相邻支座间）弦线，给出 bay 序号、
   bay 内分数、滑梭在索上的三维位置；沿弧长判定行进是否越过中间支座。
2. **悬索求解**：bay 承受钢索均布自重与各坠落点止坠力（浅索近似、水平张力分量恒定），
   以弹性相容方程（几何伸长 = 弹性伸长）二分迭代求张力，给出各坠落点动态下挠、
   最大下挠、左右端反力；全跨各支座反力按加载 bay 解 + 其余 bay 预张力/自重叠加。
3. **单人及同跨多人组合**：同站同 bay 的每人单人组合（逐人净空）+ 全员同时坠落组合
   （挠度限值与支座反力的结构包络）；止坠力与下挠定点迭代至一致。`CableResult` 中
   `total_fall_m` 按 `falling_persons` 同序返回每人总坠距。
4. **下结论规则**：
   - **不下结论**（`conclusive=false`、`passable=false`，响应 `open_items`）：
     连续性断开（`continuity_break`）、滑梭卡在不可通过支座（`shuttle_jammed`）、
     重复占用（`duplicate_occupancy`，含同一人 A/B 钩同站挂同一滑梭）、参数缺失
     （`missing_params`）、求解不收敛且未授权保守边界（`solver_nonconvergence`）；
   - **失效**（`failures`）：净空余量为负（`clearance`）、动态下挠超限（`sag_limit`）、
     端座/中间支座反力越限（`support_overload`）、受力方向超锥（`anchor_direction`）；
     最早失效按（站点 → 检查优先级 → 人员序）排序给出位置与动作；
   - 弹性迭代不收敛且修订**已授权**保守边界时，反力按刚性索（上界）、下挠按 H₀
     几何索形（上界），并登记 `solver_conservative_bounds` 说明项。

### Y 型双腿系绳（共享缓冲包）载荷分配

`equipment[].twin_leg` 给出时启用，与旧等长模型互斥；记录：

| 字段 | 内容 |
|---|---|
| `legs[]` | 两条实体腿：`id`、绑定钩 `hook`（A/B，永久绑定不得交叉）、原长 `leg_length_m`、轴向刚度 `axial_stiffness_kn`、连接器侧载限值 `connector_side_load_limit_kn` |
| `buffer_curve[]` | **共享**缓冲包的力—行程曲线（行程自 0 严格递增并覆盖最大行程） |
| `max_travel_m` / `energy_capacity_j` | 缓冲包最大展开行程 / 能量容量 |
| `max_included_angle_deg` | 两腿在汇接器处的允许夹角 |

求解与判定：

1. **钩腿绑定**：自动与人工换挂都把 A/B 钩绑定到实体腿；可达性按各腿原长 +
   连接器余量判定。人工动作可带 `leg` 字段复核，绑错腿直接 422。
2. **接载次序**：逐站按各腿在竖直坠落路径上的张紧时刻（松弛量）排序，先张紧的
   腿单独承拉，第二腿张紧后进入双腿汇接器平衡。
3. **能量 + 变形协调**：汇接器三向平衡 `ΣTᵢuᵢ=(0,0,F)` 与能量方程
   `mgh = ∫F(s)ds + ΣTᵢ²/(2kᵢ)` 联立（主动集 Newton，多初值），外层二分求缓冲
   展开量 `s*`；**缓冲能只积分一次**，两腿弹性能分别计入。
4. **响应**：每站一条 `twin_leg_results`，含接载次序 `engagement_order`、
   缓冲展开量、人体峰值制动力 `buffer_force_kn`、逐腿张力/竖直与水平（侧载）
   分量、锚点坐标、两腿夹角、汇接器位置、能量供需与全部 `adopted_params`。
5. **阻断项**（定位首个站点与动作，绝不标为可通行）：
   - 曲线能量不足 / 能量容量超限、人体峰值制动力超限、夹角越限、连接器侧载越限、
     净空不足 → `failures`（`buffer_energy` / `arrest_force` /
     `included_angle` / `connector_side_load` / `clearance` 等）；
   - 绑定腿长度不足 → `leg_length_insufficient`；载荷分配求解不收敛 →
     `twin_leg_nonconvergence`（不下结论，`conclusive=false`）；两腿滑梭分属
     不同跨段 → `twin_leg_cross_span`（不下结论）。
6. 含滑梭腿时以人体峰值制动力（单人一个竖直合力）加载 bay，与悬索下挠定点迭代，
   用动态挂点重算载荷分配并替换静态结果（缓冲仍只计一次）。

### 修订治理（改跨 / 换滑梭 / 换系绳 / 保守边界）

- 柔性跨段/端座/支座的**结构性修改**（端座、预张力、线密度、弹性参数、挠度限值、
  滑梭过支座能力、容许人数等）或更换滑梭，**必须另存修订**（POST `.../revisions`）
  并在 `changes` 中附 `span_change` / `shuttle_change` 理由；PUT 覆盖草稿对这类
  修改返回 409，以保留旧版冻结参数（非结构参数如人员、动作次序仍可覆盖草稿）。
- **修改 Y 型双腿系绳**（任一腿原长、轴向刚度、连接器侧载限值、钩腿绑定，或缓冲
  力—行程曲线、最大行程、能量容量、允许夹角）同样必须另存修订并附
  `lanyard_change` 理由；草稿原地覆盖返回 409，确认稿只读。
- 采用保守边界须在 `changes` 中附 `conservative_bounds` 理由，否则 422。
- 确认版（confirmed）只读，分析不落库，旧版分析始终按该版冻结参数重算。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/plans` | 创建方案，同时保存第 1 版修订（草稿），返回该版核算结果 |
| GET | `/plans` / `/plans/{id}` | 方案列表 / 方案及其修订元信息 |
| POST | `/plans/{id}/revisions` | **另存修订**：人工调序或换装备后的新版本（rev_no 递增） |
| GET | `/plans/{id}/revisions/{n}` | 回看任一修订：动作序列、失败依据、剖面标注均由**该版参数重算** |
| GET | `/plans/{id}/revisions/{n}/analysis` | 仅取该版重算的核算结果 |
| PUT | `/plans/{id}/revisions/{n}` | 覆盖草稿参数；**确认稿返回 409，不可覆盖** |
| POST | `/plans/{id}/revisions/{n}/confirm` | 确认定稿，定稿后冻结 |

分析结果不落库：每次回看都从该修订保存的参数重新计算，保证各版本互相独立。
